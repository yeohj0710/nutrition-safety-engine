# v4.0 판단 기록

## 검색 범위와 검색식

- HRS1~HRS5의 질문 정의는 `research/searches_v3/ai_picos/picos_definition.json`을 그대로 사용했다.
- 각 검색식은 P(대상)와 I(보충제·허브 노출) 블록만 `AND`로 결합했다. 각 블록 안에서는 MeSH와 `[tiab]` 자유어를 `OR`로 결합했다.
- 2022-01-01~2026-07-28 출판일 범위는 프로토콜이 허용한 시간 범위이므로 유지했다. 결과·비교·사람·연구설계·언어·출판유형 제한은 사용하지 않았다.
- 탐침 건수가 총 48,046건으로 커졌지만 검색식을 좁히지 않았다. 높은 건수는 재현성 있는 전량 인출과 선별로 처리했다.
- PubMed 질의의 구성은 Cochrane Handbook 4장과 MECIR C32~C36의 검색식 원칙에 맞췄다. 다만 이번 프로토콜은 PubMed만 지정했으므로 다중 데이터베이스 검색, 인용 검색, 전문 검색가 동료 검토 등 MECIR 전체 절차를 충족했다고 판단하지 않았다.

## 인출과 중복 처리

- 탐침과 인출을 분리했다. Phase A에서는 ESearch 건수만 확인했고, Phase B에서 질문별 전량을 EFetch로 받았다.
- DOI가 있으면 정규화한 DOI를 중복 키로 썼고, DOI가 없으면 제목 완전일치를 사용했다.
- 질문 안의 중복 15건만 제거했다. 같은 논문이 서로 다른 질문에 포착된 경우 질문별 판정 단위를 보존했다.
- 첫 HRS1 인출 시도의 불완전 산출물은 삭제하지 않고 `research/searches_v4/etc/failed_runs/`에 격리했다. 최종 원본은 run ID `20260728T014125Z`만 코퍼스에 연결했다.

## 전량 선별

- 판정 프롬프트를 실행 전에 동결했다. 프롬프트 SHA-256은 `55f7b08f8d7af7e5e9553e093558438cdccc5c4b3365e1c4acb6300302c5b4a3`이다.
- 48,031개 질문-논문 행을 196개 비중복 배치로 나누고 8개 서브에이전트 담당 구간을 고정했다.
- 허용 판정은 `retain`, `deprioritize`, `uncertain`뿐이다. 모든 판정에 사유 코드, 확신도, `abstract` 또는 `title_only` 근거 구분을 기록했다.
- 초기 작업기 세 버전은 독립 표본에서 의미 오류가 확인되어 최종 체크포인트에 합치지 않았다. 실패 산출물은 `research/screening/v40_agent/etc/failed_classifier_*` 아래에 보존했다.
- 최종 작업기는 출판유형 문자열의 존재만으로 `design_signal`을 부여하지 않도록 바꿨다. 실제 설계 표현이나 구체 연구 출판유형이 있을 때만 신호를 부여하고, 정정·답신·논평이 인용한 원 연구의 설계를 현재 기록에 상속하지 않았다.
- 기존 경계 사례 313건과 이번 독립 감사 303건, 총 616건을 에이전트 재판정 파일로 고정했다. 원시 규칙은 616건 중 390건에서 재판정과 일치했고 226건에서 달랐다. 이 차이는 숨기지 않고 `semantic_rule_audit.json`에 기록했다. 최종 산출물에는 해시가 고정된 616건의 에이전트 재판정을 우선 적용했다.
- HRS3 PMID 36342076은 두 감사에서 판정이 갈렸다. 제목은 모계 유전성 안질환에 대한 가설적 비타민 A 치료 질문이며 임신 중 보충제 노출 연구가 아니므로 `deprioritize`로 정리했다.
- 사람 기준 판정 자료는 없으며 모든 판정 주체는 Codex 에이전트다. 따라서 선별 성능을 사람 판정에 대한 지표로 해석하지 않는다.
- 에이전트의 판정 방식은 두 층이다. 48,031행 전량의 라벨은 에이전트가 작성하고 감사한 결정적 판별 작업기(`tools/v40/agent_screen_worker.py`, `v40_deterministic_text_assist_3.3.0`)가 제목·초록의 노출·결과·설계·전임상·경로·인구 표현을 직접 판별해 부여했다. 작업기가 가르지 못하는 경계 사례 616건(1.3%)은 에이전트가 원문을 읽고 직접 재판정해 덮어썼다. 즉 "에이전트가 수행했다"는 매 건을 개별 추론으로 읽었다는 뜻이 아니라 판별 규칙의 저작·감사와 경계 사례 판정을 에이전트가 했다는 뜻이다. 이 방식은 작업기 해시가 고정되어 있어 같은 입력에 같은 라벨이 재현된다.

## 하류 산출물

- v3.0 코드는 읽어서 재사용하되 모든 쓰기 경로를 `research/systematic_review_v40/`으로 고정했다.
- 근거 번들은 `retain`이면서 정규식 주제 게이트를 통과한 행만 사용한다. 질문별 핵심 근거는 우선순위 상위 15건으로 제한한다.
- 한국어 번역은 5개 질문을 별도 에이전트에 배정했다. 원문 수치·단위·효과 방향을 보존하는 검사에 통과한 번역만 합친다.
- 개인화 규칙은 근거 문장을 연결하는 용도로만 만든다. 임상 판단, 복용 시작·중단, 용량 변경을 지시하지 않도록 출력과 메타데이터를 중립화했다.
- 사이트 배포와 원격 저장소 전송은 작업 범위에서 제외했다.

## 남은 제한

- PubMed 밖의 데이터베이스와 회색문헌은 검색하지 않았다.
- 사람의 독립 선별과 전문 검색가의 동료 검토는 수행하지 않았다.
- 전문 원문은 관찰하지 않았으며 제목·초록 정보만 사용했다.
- 최종 연구 선정 수, 통합 분석, 편향 평가, 근거 확실성 평가, 임상 지침은 만들지 않았다.
- 근거 번들은 에이전트 `retain` 판정과 정규식 주제 게이트를 **모두** 통과한 행만 담는다.
  이 때문에 에이전트가 `retain`으로 판정한 3,374행 중 1,475행(43.7%)이 정규식 게이트에서
  탈락해 번들에 들어가지 않았다. 질문별 탈락은 HRS3 727, HRS1 316, HRS4 241, HRS2 165,
  HRS5 26이다. 정규식 게이트는 문장 로케이터와 용량 값을 추출할 수 있는 행만 통과시키는
  결정론적 장치이며, 선별 판정 자체를 대체하지 않는다. 다만 **선별 판정은 100% 에이전트
  책임이고(작업기 저작·감사와 경계 616건 재판정) 근거 번들 진입에는 이와 별개의 정규식
  게이트가 함께 작용한다**는 점을 명시한다. 선별의 결정적 작업기와 번들의 정규식 게이트는
  서로 다른 장치이며, 후자는 문장 로케이터·용량 추출 가능 여부만 본다.
  대응 수치는 `research/systematic_review_v40/regex_gate.csv`에 행 단위로 남아 있다.
- `uncertain` 60건은 전부 초록이 없는 `title_only` 행이다. 초록이 있는 47,190행에서는
  `uncertain`이 한 건도 발생하지 않았다. 이 라벨은 판단 불확실이 아니라 관찰 자료 부족을
  뜻하므로, 선별 신뢰도 지표로 해석하지 않는다.
- 제외 사유 코드 `off_topic`은 `deprioritize` 44,597건 전체에 부여되어 있어 제외 사유를
  세분하지 않는다. 사유별 분해가 필요하면 재분석이 필요하다.
- 핵심 근거 75건은 근거 부족이 아니라 질문당 상한 15건(`MAX_CORE_PER_QUESTION`)의 결과다.
  상한 적용 전 후보는 근거 번들 1,899건이다.
