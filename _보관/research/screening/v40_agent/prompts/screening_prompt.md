# v4.0 에이전트 전량 선별 판정 기준

이 문서는 v4.0 코퍼스의 제목·초록 선별 기준을 고정한다. 실행이 시작된 뒤에는 수정하지 않는다.
판정 주체는 Codex 하위 에이전트이며, 외부 선별 API나 별도 로컬 언어모델을 호출하지 않는다.

## 1. 판정 목적과 경계

고위험 임상상황의 영양·허브 보충제 안전성 문헌지도를 만든다. 이 판정은 사람의 최종 문헌
선정이 아니다. 모든 레코드-질문 행에 `retain`, `deprioritize`, `uncertain` 중 하나를 기록한다.
임상 권고, 복용 시작·중단, 용량 결정, 사람이 확인했다는 주장을 만들지 않는다. 제목·초록에
없는 사실을 만들지 않는다.

## 2. 라벨

| 라벨 | 기준 |
| --- | --- |
| `retain` | 질문의 대상집단·고위험 상황(P), 보충제·허브 노출(I), 안전성 결과·상호작용(O)이 함께 다뤄질 가능성이 있다. P·I·O 중 둘 이상이 명확하고 나머지 하나가 부정되지 않아도 유지한다. |
| `deprioritize` | P, I, O 중 하나가 명확히 부정된다. 보충제가 아닌 노출, 안전성 신호가 없는 효능 전용 연구, 동물·시험관 전용 연구, 논평·소식·정정만 있는 기록도 여기에 둔다. |
| `uncertain` | 제목·초록만으로 P·I·O 중 하나 이상을 판단할 정보가 부족하고 명확한 부정도 없다. |

경계가 모호하면 `uncertain`을 사용한다. 검색식이 넓어서 관련 없는 레코드가 많은 것은 정상이다.

## 3. 행별 판정 순서

1. P: 질문의 대상집단·상황인가. 동물·시험관 전용이면 `animal_term_present`와
   `deprioritize`를 기록한다.
2. I: 식이보충제, 비타민, 무기질, 허브·식물성 제제, 기능성 성분의 보충 노출인가.
   일반 식품 섭취, 식사 패턴, 처방의약품 단독은 I가 아니다.
3. O: 이상반응, 독성, 출혈, 전해질 이상, 간손상, 기형, 상호작용, 검사치 이상, 입원,
   사망 같은 안전성 결과가 있는가. 효능 결과만 있으면 `deprioritize`한다.
4. S: 임상시험, 관찰연구, 증례, 등록자료, 약물감시, 체계적·서술적 종설, 지침에서 안전성
   정보를 확인할 수 있다. 사설, 학회 소식, 정정문만 있으면 `deprioritize`한다.

## 4. 질문별 주의점

- HRS1_PERIOPERATIVE: 수술·침습적 시술과 수술 전후 노출이 대상이다. 소아만 다루면 P가 아니다.
- HRS2_KIDNEY_DISEASE: 만성콩팥병·투석 환자와 비처방 비타민·무기질·허브 노출이 대상이다.
  일반 식품의 영양소 함량이나 식사 패턴만 다루면 I가 아니다.
- HRS3_PREGNANCY: 임신 중 노출과 산모·태아·신생아 안전성이 대상이다. 임신 노출과 연결되지
  않은 신생아 보충 연구는 P와 I를 함께 충족하지 않는다.
- HRS4_LIVER_DISEASE: 기존 간질환자뿐 아니라 보충제로 발생한 간손상 자체를 다룬 기록도 P를
  충족한다. 보충제가 아닌 처방약 단독 간손상은 I가 아니다.
- HRS5_ANTICOAGULATION: 항응고제를 사용하는 환자가 P다. 항혈소판제만 다루면 P가 아니지만,
  항응고제와 항혈소판제를 함께 다루면 P를 충족할 수 있다.

## 5. reason_codes

다음 값만 사용한다. 하나 이상을 기록한다.

- `population`: 질문의 대상집단·상황이 확인된다.
- `exposure`: 보충제·허브 노출이 확인된다.
- `outcome`: 안전성 결과·상호작용이 확인된다.
- `human_signal`: 사람 대상 신호가 확인된다.
- `design_signal`: 판단 가능한 연구설계가 확인된다.
- `animal_term_present`: 동물·시험관 전용 연구다.
- `off_topic`: 질문과 주제가 뚜렷이 다르거나 P·I·O 중 하나가 명확히 부정된다.
- `insufficient_abstract`: 초록이 없거나 판단 정보가 부족하다.

## 6. confidence와 근거 기반

- `high`: P·I·O가 모두 명시적이거나 명백한 불일치가 있다.
- `medium`: 두 요소가 명시적이고 나머지 하나를 문맥에서 판단한다.
- `low`: 한 요소만 확인되거나 초록이 없다.
- 초록이 있으면 `evidence_basis=abstract`다.
- 초록이 없으면 `evidence_basis=title_only`, `confidence=low`, reason_codes에
  `insufficient_abstract`를 반드시 기록한다.

## 7. 출력

행마다 JSON 한 줄을 쓴다.

```json
{"record_id":"pubmed:NNNNNNNN","question_id":"HRS1_PERIOPERATIVE","decision":"retain","reason_codes":["population","exposure","outcome"],"confidence":"high","evidence_basis":"abstract","status":"ok"}
```

`status`는 항상 `ok`다. 모든 입력 키를 정확히 한 번 반환한다.
