# 전체 연구 실행 청사진

## 1. 연구 정체성

이 연구는 넓은 범위의 영양제 정보를 보여주는 웹사이트 제작 과제가 아니다. 또한 검색 결과를 나열하는 종설도 아니다. 중심 연구 문제는 다음과 같다.

> 고위험 임상상황에서 영양보충제 안전성 근거를 재현 가능한 방법으로 찾고, 사람이 검증한 구조화 자료로 바꾼 뒤, 그 근거만 사용하여 상황별 상담 우선순위를 제시하는 결정적 규칙 도구를 만들 수 있는가?

연구의 학술적 기여는 세 가지다.

1. 임상적으로 서로 다른 다섯 질문을 사전에 고정하고, 보고서가 아니라 **연구 단위**로 근거를 정리한다.
2. 대규모 언어모델을 사용했다는 사실이 아니라, 사람이 만든 정답과 비교하여 **어떤 작업에서 얼마나 정확하고 어떤 오류를 보였는지** 평가한다.
3. 문헌 요약과 앱 문장을 느슨하게 연결하지 않고, `원문 위치 → 근거 주장 → 규칙 → 시나리오 결과`의 추적 사슬을 검증한다.

## 2. 연구 범위

### 2.1 필수 임상 질문

| ID | 임상상황 | 노출 | 핵심 결과 |
|---|---|---|---|
| A1 | 비타민 K 길항제, 특히 warfarin 복용 성인 | 비타민 K 보충 또는 섭취량 변화 | INR 변동, 치료범위 유지, 출혈, 혈전색전 사건 |
| A2 | 경구 항응고제 복용 성인 | omega-3/fish oil/EPA/DHA | 주요 출혈, 임상적으로 유의한 비주요 출혈, 전체 출혈 |
| B1 | 칼슘옥살산 신결석 또는 고칼슘뇨 위험 성인 | 보충제 칼슘 | 결석 발생·재발, 요중 칼슘, 고칼슘혈증 |
| B2 | 같은 신장 고위험군 | 비타민 D 단독 또는 칼슘과 병용 | 고칼슘뇨, 고칼슘혈증, 결석 발생·재발 |
| B3 | 같은 신장 고위험군 | 비타민 C | 요중 옥살산, 결석 발생·재발, 신기능 관련 위해 |

### 2.2 범위 밖 항목

CoQ10, 글루코사민·콘드로이틴, 멀티비타민, 밀크씨슬, 레보티록신·칼슘, 퀴놀론·칼슘, 임신·종합비타민 등은 기존 앱에 존재하더라도 본 논문의 검증 범위가 아니다. 다음 중 하나로 처리한다.

- `exploratory_demo`: 연구 결과와 분리된 탐색 기능
- `legacy_unverified`: 과거 규칙이며 원문 재검증 전 비노출
- `future_scope`: 후속 연구 후보

논문의 규칙 수와 성능 지표에는 `validated_thesis_scope`만 포함한다.

### 2.3 범위 축소 안전장치

다섯 질문 모두를 완성하기 어렵다는 사실이 검색 단계에서 확인되면, 임의로 얕게 끝내지 않는다. 프로토콜 변경을 기록하고 다음 우선순위를 적용한다.

1. A1과 A2를 필수 핵심 질문으로 유지한다.
2. B1~B3 중 원문 근거가 충분하고 임상적으로 구분 가능한 질문을 유지한다.
3. 제외한 질문은 검색·선별 현황과 제외 이유를 부록에 투명하게 보고한다.
4. 변경은 결과를 본 뒤 유리한 질문만 남기는 방식으로 할 수 없다. 변경일, 근거, 영향, 승인자를 기록한다.

## 3. 연구 설계

### 3.1 연구 1: 체계적 근거검토

각 질문에 독립적인 검색식을 사용한다. 하나의 거대한 검색식으로 항응고제, 신결석, 다섯 성분을 한꺼번에 묶지 않는다. 검색원별 원본 내보내기 파일을 보존하고, 제목·초록 선별과 원문 선별을 분리한다.

분석 단위는 `study`다. 같은 임상시험의 논문, 보조분석, 후속 논문은 여러 `report`로 보존하되 하나의 `study_id`로 묶는다. 체계적 문헌고찰, 공공기관 자료, 1차 임상연구는 서로 다른 근거층으로 관리하며 같은 수치 산출에 중복 포함하지 않는다.

### 3.2 연구 2: AI 보조 성능평가

AI는 다음 작업에만 사용한다.

- 제목·초록 단계에서 사람이 먼저 볼 순서 제안
- 원문에서 사전 지정 필드의 후보 값 추출
- 후보 값마다 짧은 원문 인용과 페이지·표·절 위치 제시
- 근거 주장 초안의 논리적 필드 채우기

AI는 다음 작업을 단독 수행할 수 없다.

- 문헌 자동 제외
- 원문 없이 안전성 결론 작성
- 용량 임계값이나 금기 수준 결정
- 비뚤림 위험 최종 판정
- 근거확실성 최종 판정
- 규칙의 임상 우선순위 확정

정답 자료는 사람이 먼저 확정하고 잠근다. 그 뒤 모델 출력과 비교한다. 프롬프트 개발 자료와 최종 평가 자료를 분리하고, 같은 문헌으로 프롬프트를 다듬고 성능을 보고하지 않는다.

### 3.3 연구 3: 결정적 규칙 도구 개발 및 검증

실행 시점에는 생성형 모델이 임상 문장을 새로 쓰지 않는다. 검증된 규칙과 고정된 메시지 템플릿만 사용한다. 모든 결과는 규칙 ID와 근거 주장 ID를 반환한다.

권장 출력 단계는 다음과 같다.

1. `urgent_referral`: 즉시 전문적 평가가 필요한 위해 신호
2. `avoid_until_review`: 검토 전 시작·증량을 보류할 상황
3. `pharmacist_review`: 복용 조건과 병용 약물 확인이 필요한 상황
4. `monitor_or_consistency`: 일관성 유지 또는 모니터링이 핵심인 상황
5. `information_only`: 위해 판단이 아니라 일반 정보
6. `insufficient_evidence`: 현재 근거로 판단 강도를 높일 수 없는 상황

“복용 가능”, “안전함”, “금지”처럼 임상 판단을 과도하게 단정하는 표현은 사용하지 않는다.

## 4. 연구 흐름과 단계별 잠금

### Gate 0. 현 상태 감사

- 저장소와 배포 버전 확인
- 과거 산출물 해시와 경로 기록
- 기존 숫자 불일치 목록 작성
- 연구 범위 밖 규칙 분리

### Gate 1. 프로토콜 고정

- 연구 질문과 결과 정의
- 포함·제외 기준 확정
- 검색원 접근성 확인
- AI 평가 계획과 검증 지표 확정
- 윤리·기관 검토 필요 여부 확인

이 단계가 끝나기 전에는 최종 검색을 실행하지 않는다.

### Gate 2. 검색 고정

- 질문별 검색식 동료 검토
- 모든 검색원에서 최종 실행
- 원본 파일, 총 결과 수, 실제 내보낸 수, 해시 기록
- 상위 N개만 저장하는 제한 제거

### Gate 3. 선별 고정

- 중복 제거 결과 검증
- 제목·초록 결정 완료
- 원문 확보와 제외 사유 완료
- 연구·보고서 연결 완료
- PRISMA 수치 재생성

### Gate 4. 추출·질평가 고정

- 핵심 필드 이중 확인
- 비뚤림 위험 평가 완료
- 근거 주장마다 원문 위치 확인
- AI 성능평가 자료 잠금

### Gate 5. 합성 고정

- 질문별 합성 방법 결정
- 가능한 경우 정량합성, 불가능한 경우 구조화 서술합성
- 결과별 근거확실성 평가
- 결론 강도와 불확실성 명시

### Gate 6. 규칙 고정

- 검증 가능한 근거 주장만 규칙으로 전환
- 규칙마다 적용 범위, 예외, 누락정보, 메시지 확정
- 모든 링크 무결성 검사

### Gate 7. 검증 고정

- 독립적으로 작성한 시나리오 정답 세트 잠금
- 엔진 성능과 오류 유형 분석
- 전문가 내용 검토
- 조건부 사용성 평가

### Gate 8. 논문 고정

- 데이터 버전과 분석 코드 태그 지정
- 표와 그림 자동 생성
- 결과를 먼저 쓰고 고찰과 초록을 나중에 작성
- 수치·참고문헌·앱·부록 일치 검사

## 5. 검색 설계의 핵심 규칙

- PubMed/MEDLINE 한 곳만 검색했다고 체계적 검토로 부르지 않는다.
- MEDLINE, Embase 접근 가능 시 Embase, CENTRAL을 우선 검색한다.
- Scopus 또는 Web of Science 중 접근 가능한 하나를 추가한다.
- ClinicalTrials.gov와 WHO ICTRP로 미출판·진행 연구를 확인한다.
- KoreaMed, KMbase, RISS 등 국내 자료원은 접근성과 중복을 검토해 사용한다.
- NIH ODS, NCCIH, EFSA, MFDS, 한국인 영양소 섭취기준 등은 `guidance_source` 층으로 분리한다.
- Crossref는 DOI 확인과 서지 보완 도구다. 독립적인 임상 근거 데이터베이스의 검색 hit처럼 합산하지 않는다.
- Europe PMC는 누락 확인과 원문 접근 보조로 사용할 수 있지만 PubMed와 겹치는 결과를 독립 근거 규모로 표시하지 않는다.
- 관련도 정렬 상위 100건만 저장하는 방식은 최종 검색으로 인정하지 않는다.
- 검색일, 플랫폼, 전체 검색식, 제한, 총 결과 수, 내보낸 수, 파일 해시를 모두 남긴다.

## 6. 선별 설계

### 6.1 사람 검토

- 1차 검토자는 모든 제목·초록을 본다.
- 2차 검토자는 모든 `include`와 `uncertain`, 그리고 제외 표본의 층화 무작위 20% 이상을 독립 검토한다.
- 모든 원문은 두 사람이 독립 검토한다.
- 불일치는 합의 후 제3 검토자 또는 지도교수 판단으로 해결한다.
- 합의 전 원래의 두 판단을 보존한다.

자원이 허용되면 제목·초록도 전수 이중 선별한다. 부분 이중 선별을 사용한 경우 논문에서 이를 명시하고, 제외 표본에서 발견된 오류율을 보고한다.

### 6.2 AI 우선순위

AI 점수는 화면 정렬에만 사용한다. AI가 낮게 평가한 문헌도 사람이 정한 표본 검토와 중지 규칙을 통과하기 전 제외하지 않는다. 성능은 민감도, 특이도, 정밀도, 음성예측도, F2, 작업절감률을 보고한다. 가장 중요한 지표는 포함 문헌을 놓치지 않는 민감도다.

## 7. 정보추출과 근거 주장

각 수치는 다음 필드를 가져야 한다.

- `study_id`, `report_id`, `source_id`
- 대상자와 설정
- 노출의 형태, 용량, 기간
- 비교군
- 결과의 정의와 측정 시점
- 사건 수, 분모, 효과크기, 신뢰구간
- 조정 여부와 조정 변수
- 원문 인용
- 페이지, 표, 그림, 부록 위치
- 추출자와 검증자
- 비뚤림 위험 판단
- 적용 가능한 임상 질문

한 문헌의 초록만 보고 수치를 확정하지 않는다. 원문을 확보하지 못한 자료는 `awaiting_full_text` 또는 `abstract_only_context`로 표시하고 핵심 규칙의 근거로 사용하지 않는다.

## 8. 비뚤림 위험과 근거확실성

- 무작위시험: RoB 2
- 비무작위 중재연구: 적절한 ROBINS 계열 도구
- 코호트·환자대조 등 노출 연구: 프로토콜에서 정한 적절한 도구를 일관되게 적용
- 사례보고·사례군: 위해 신호 자료로만 사용하며 별도 체크리스트 적용
- 기존 체계적 문헌고찰: 배경과 인용추적에 사용하고 필요 시 AMSTAR 2 평가
- 공식기관 자료: 기관 권위, 최신성, 근거 인용, 직접성, 업데이트일을 별도 평가

GRADE는 질문별 중요 결과의 근거 묶음에 적용한다. 개별 문헌에 임의의 “레벨 1, 2, 3”을 붙이는 방식으로 대체하지 않는다. 근거확실성과 권고 강도도 동일한 개념이 아니다.

## 9. 합성 계획

질문과 연구설계가 충분히 동질적이고 독립 연구가 세 편 이상일 때만 메타분석을 검토한다. 다음을 분리한다.

- VKA와 DOAC
- omega-3 혼합제와 고용량 정제 EPA
- 식이 칼슘과 보충제 칼슘
- 비타민 D 단독과 칼슘·비타민 D 병용
- 신규 결석과 재발 결석
- 임상 사건과 생화학 지표
- 조정 효과와 비조정 효과

무리한 통합보다 질문별 근거표와 구조화 서술합성을 우선한다. 통합하지 않은 이유도 결과로 기록한다.

## 10. AI 평가 설계

### 10.1 선별 평가

- 프롬프트 개발 세트: 최대 50건, 최종 성능 분석에서 제외
- 평가 세트: 가능한 경우 사람 선별 전체 자료
- 포함 문헌 수가 적으면 모든 포함과 무작위 제외를 사용하되 표본 구성 공개
- 반복 실행: 고정된 모델·설정으로 최소 3회
- 필수 보고: 모델명, 버전 또는 접근일, 프롬프트 해시, 온도, 입력 해시, 출력 해시

### 10.2 추출 평가

- 평가 대상: 최종 포함 원문 최소 30편 또는 전수
- 명시 필드와 해석 필드 분리
- 필드별 정확도·정밀도·재현율·F1
- 숫자 정확성, 단위 정확성, 원문 위치 정확성
- 원문에 없는 주장 비율
- 반복 실행 간 일치율
- 사람이 수정하는 데 걸린 시간과 오류 유형

AI가 생성한 한국어 요약의 “자연스러움”은 1차 평가변수가 아니다. 연구의 핵심은 사실 정확성, 추적 가능성, 안정성이다.

## 11. 규칙 작성 원칙

규칙은 논문 문장보다 더 엄격해야 한다.

- 하나의 규칙은 하나의 명확한 임상 행동 우선순위를 가진다.
- 근거가 상충하면 강한 단정 대신 `pharmacist_review` 또는 `insufficient_evidence`를 사용한다.
- 임계값은 원문이나 권위 있는 기준에서 직접 확인한 경우에만 사용한다.
- 대상자, 제형, 용량, 기간, 병용 약물을 생략한 일반화는 금지한다.
- 규칙의 메시지에는 “왜”, “무엇을 더 확인해야 하는지”, “어떤 상황에서 적용되지 않는지”가 포함된다.
- 모든 규칙은 적어도 하나의 검증된 `claim_id`를 참조한다.
- 심각도와 근거확실성을 혼동하지 않는다. 심각하지만 근거가 약한 위해 신호도 있을 수 있다.

## 12. 검증 설계

### 12.1 데이터 무결성

- 검증 범위의 규칙 100%가 근거 주장과 원문 위치에 연결되어야 한다.
- 끊어진 링크, 존재하지 않는 출처, 단위 변환 불일치는 0건이어야 한다.
- 같은 입력의 반복 실행 결과는 100% 동일해야 한다.

### 12.2 시나리오 검증

목표 120건:

- 직접 양성 60건
- 경계·음성·범위 밖 30건
- 상충 근거·누락정보·복합 조건 30건

정답은 엔진 개발자가 아닌 두 명의 검토자가 독립 작성하고 합의한다. 핵심 성능 목표는 다음과 같다.

- 고위험 규칙 민감도 0.95 이상
- 전체 정밀도 0.85 이상
- 규칙 집합 완전일치율 0.80 이상
- 중대한 거짓 음성 0건
- 근거 링크 정확도 1.00
- 결정성 1.00

목표를 통과하지 못해도 결과를 숨기지 않는다. 오류 분석과 수정 전후 비교를 연구 결과로 보고한다.

### 12.3 전문가 검토와 사용성

약사 또는 관련 임상 전문가 3명 이상에게 범위, 정확성, 표현, 행동 가능성, 위해 가능성을 평가받는다. 전문가 수가 부족하면 “내용 타당도 검증”이라고 과장하지 않고 “형성적 전문가 검토”로 보고한다.

사람을 대상으로 한 사용성 평가는 기관의 IRB 또는 비대상·면제 판단을 먼저 문서로 확인한 경우에만 시행한다. 승인 전에는 참가자를 모집하거나 데이터를 수집하지 않는다.

## 13. 저장소 원칙

- 원자료는 불변으로 보존한다.
- 검색, 선별, 추출, 주장, 규칙, 검증 결과는 서로 다른 테이블로 관리한다.
- 모든 데이터는 스키마 검사를 통과해야 한다.
- 앱 수치는 소스 코드에 직접 적지 않고 정식 데이터에서 계산한다.
- 앱의 사용자 화면과 연구 감사 화면을 분리한다.
- `thesis_mode=true`에서는 검증된 연구 범위만 노출한다.
- 생성형 모델 호출은 오프라인 연구 스크립트에만 둔다.
- CI는 스키마, 추적성, 단위 테스트, 시나리오, 빌드를 모두 검사한다.

자세한 구조는 `07_REPO/repo_redesign_spec.md`를 따른다.

## 14. 논문 구조

실제 본문 목표는 35~50쪽이지만, 쪽수는 통과 기준이 아니다.

1. 서론 4~6쪽
2. 연구대상 및 방법 10~14쪽
3. 결과 10~14쪽
4. 고찰 8~10쪽
5. 결론 1~2쪽
6. 부록: 전체 검색식, 원문 제외 목록, 추출 사전, AI 프롬프트·평가표, 규칙 목록, 시나리오

방법과 결과는 연구 1·2·3의 순서가 서로 대응해야 한다. 결과가 없는 방법은 줄이고, 방법에 없는 결과는 넣지 않는다.

## 17. 중단 금지 규칙
