# v3.0 작업 계획 — 전 과정 AI 자율 수행

작성 2026-07-27. 실행 주체는 로컬 AI 에이전트(Codex 등)다. OpenAI API 키를 쓰지 않는다.

이 문서는 `v2.1-measured-screening-plan.md` 의 후속이다. v2.1 은 LLM 분류층을 만들었지만
65.8% 에서 멈췄고 파생 체인에 반영되지 않았다. v3.0 은 그 층을 완주시키고, 그 위에
**연구질문 설계까지 AI 가 수행하는 병렬 트랙**을 신설한다.

## 3. 절대 금지

프로토콜 위반과 과거에 실제로 발생한 사고를 모두 포함한다.

**연구 무결성**
1. 사람 gold 가 없는 지표를 사람 gold 인 것처럼 쓰지 않는다. §7 명명 규칙을 반드시 따른다.
2. PRISMA 최종 포함·제외 수, 메타분석, 통합 효과크기, RoB·GRADE 사람 평가, 임상 권고를
   만들지 않는다. 라벨은 `retain` / `deprioritize` / `uncertain` 이며 include/exclude 가 아니다.
3. 접근하지 못한 자료원을 근거 부재로 해석하지 않는다.
4. 모든 숫자는 코드와 입력 해시에서 재생성한다. 하드코딩하지 않는다.

**자료 보존**
5. v2.1 코퍼스를 재검색·재수집하지 않는다. `research/searches/` 의 기존 실행,
   `efetch_*.xml`, `checksum.sha256` 을 수정하지 않는다. v3.0 검색은 **새 경로**에만 쓴다.
6. `data/curated_v2/evidence_map.csv` 를 수정하지 않는다. 입력 해시
   `7fbd8cab64c7ba874ec95c759c9597684151b020e4fdc4f708afbbdabf5aa7c2` 가 끝까지 유지돼야 한다.
7. 체크포인트 JSONL 을 절대 잘라내거나 다시 쓰지 않는다. append 만 한다.

**과거에 실제로 터진 함정**
8. `.gitattributes` 의 `-text` 규칙을 건드리지 않는다. `core.autocrlf=true` 가 CSV 필드 내부
   개행까지 CRLF 로 바꿔 기록 해시를 깬 적이 있다. 단 파생 산출물
   (`data/curated_v2/*.jsonl`, `src/generated/ai-exploratory-bundle.json`)에는 `-text` 를
   걸면 안 된다 — 걸면 번들 재빌드 결정성 검사가 첫 실행에서 실패한다.
9. `src/generated/legacy/knowledge-index.json` 은 dev 워처가 재생성하면 CRLF 로 바뀐다.
   커밋 전 `git checkout --` 로 되돌린다.
10. `validate_*.py` 는 읽기 전용이 아니다. 내부에서 빌드를 실행해 산출물을 덮어쓴다.
    진단 목적으로 가볍게 돌리지 않는다.
11. `LLM_GATE_MIN_COVERAGE` 는 점검 전용 환경변수다. 실제 생성 실행에 쓰지 않는다.
12. `ai_screening_classifications.csv` 는 BOM 이 있어 `utf-8-sig` 로 읽는다.
    `evidence_map.csv` 와는 `(record_id, question_id)` 로 조인한다.

## 4. 단계

우선순위 순이다. 시간이 부족하면 뒤에서부터 버린다. 각 단계는 독립적으로 커밋 가능해야 한다.

### P0 — 동결과 에이전트 분류 하네스

**P0-1. 동결.** 현재 상태를 되돌릴 수 있게 만든다.
- `git tag v2.1-frozen` 후 태그 유지
- `research/audit/v21_freeze_manifest.json` 에 주요 산출물 경로와 sha256 기록

**P0-2. 에이전트 분류 하네스.** `tools/agent_screening/` 를 만든다.
- `make_batches.py` — 미분류 행을 배치 파일로 뽑는다. 배치당 40~60행,
  각 배치는 `{batch_id, input_sha256, rows:[{record_id, question_id, title, abstract}]}`
- 에이전트가 배치를 읽고 판정해 `research/screening/llm_screening_runs.jsonl` 에 append 한다.
  줄 스키마는 기존과 **완전히 동일**해야 한다:
  `{"record_id","question_id","decision","reason_codes","confidence","status":"ok"}`
  `decision` ∈ {retain, deprioritize, uncertain}
  `reason_codes` 는 `|` 구분, 허용값은 `llm_screening.py` 의 `REASON_CODES` 와 동일
- `verify_coverage.py` — 요청한 모든 `(record_id, question_id)` 가 정확히 한 번씩
  돌아왔는지 검사하고, 누락분을 재배치 큐로 다시 뽑는다. **이 검사를 통과할 때까지 반복한다.**

판정 기준은 `llm_screening.py` 의 `SYSTEM` 프롬프트를 그대로 쓴다. 프롬프트를 바꾸면
11,850행과 이질적인 판정이 섞인다. 바꿔야 한다면 기존 11,850행도 다시 판정해야 한다.

**P0-3. 실행 모드 기록.** `llm_screening.py` 를 수정한다.
- `finalize()` 의 `incomplete_reason` 이 OpenAI 할당량 소진으로 하드코딩돼 있다. 실제 사유를
  받도록 고친다.
- 매니페스트에 `execution_mode` 를 추가한다: `api_batch` 또는 `agent_local`
- `agent_local` 인 행은 토큰 사용량 대신 `batch_id`, `batch_sha256`, 판정 시각을 남긴다
- 혼합 실행이므로 매니페스트에 행별 실행 모드 분포를 기록한다
  (예: `{"api_batch": 11850, "agent_local": 8380}`)

### P1 — 선별 100% 완주

**P1-1. 초록 보유 미분류 6,165행.** P0-2 하네스로 전량 처리.

**P1-2. 제목만 있는 2,215행.** 지금은 아예 분류 대상에서 빠져 있다. 100% 주장을 하려면
처리해야 한다. 방침:
- 제목만으로 판정하되 별도 프레임으로 분리한다
- `reason_codes` 에 `insufficient_abstract` 를 강제 부여하고, `confidence` 는 `low` 상한
- CSV 에 `evidence_basis` 컬럼 추가: `abstract` 또는 `title_only`
- 매니페스트에 두 프레임의 판정 분포를 따로 보고한다
- 비-PubMed 269행은 `source` 컬럼으로 식별해 트랙 분석에서 분리 가능하게 표시한다

**P1-3. 확정.** `python tools/llm_screening.py --finalize` 로 CSV·매니페스트 생성.
완료조건: `coverage == 1.0`, `run_complete == true`, `row_count == 20230`.

**P1-4. 방식 간 비교 재생성.** `npm run screening:compare`.
부분 실행 경고문이 제거되고 전량 기준 κ 가 나와야 한다.
`interpretation_warning` 필드를 전량 실행 문구로 교체한다.

### P2 — AI 참조표준 채점과 오차 보정

프로토콜 개정이 선행 조건이다.

**P2-1. 프로토콜 v3.0 문서와 AM-007.**
- `research/protocol/protocol-v3.0-full-ai.md` 를 신설한다. v2.0 은 v2.1 트랙에 대해
  계속 유효하고, v3.0 은 v3.0 트랙에만 적용된다. v2.0 원문을 소급 수정하지 않는다.
- v3.0 §9 대체 조항: 참조표준이 AI 로 생성된 경우, 지표 이름에 참조표준의 출처를
  명시하는 조건으로 산출을 허용한다. 사람 gold 를 사칭하는 명명은 계속 금지한다.
- `amendments.csv` 에 AM-007 기록: 사유는 사용자의 명시적 결정(전 과정 AI 수행,
  채점까지 AI), 영향은 v2.1 산출물 불변·v3.0 신규 지표 추가.
- `screening_gold_manifest.json` 의 `purpose` 가 `human gold standard` 로 돼 있다.
  `ai_reference_standard` 로 고치고 개정 이력을 남긴다.

**P2-2. 채점.** `research/validation/screening_gold/screening_gold_blind.csv` 420행.
독립성을 최대한 확보한다.
- 분류 단계와 **다른 프롬프트**를 쓴다. 질문 적합성을 통째로 묻지 말고 PICOS 요소별
  (대상·노출·비교·결과·설계)로 분해해 물은 뒤 규칙으로 종합한다
- 분류기 출력(`ai_screening_classifications.csv`, `llm_screening_classifications.csv`)을
  절대 참조하지 않는다. 블라인드본만 읽는다
- 행 순서를 무작위화한다. 시드를 매니페스트에 기록한다
- **3회 독립 판정** 후 다수결. 3-way 불일치는 `unresolved` 로 남기고 지표에서 제외하되
  건수를 보고한다
- 출력 `research/validation/screening_gold/ai_reference_scores.csv`,
  매니페스트에 모델·프롬프트 해시·시드·라운드별 분포·라운드 간 일치도 기록

**P2-3. 지표.** `tools/evaluate_against_ai_reference.py` 를 만든다.
- 층화 가중치(`strata[].weight`)를 반드시 적용한다. 단순 평균은 틀린다
- 규칙 기반·LLM 각각에 대해 참조표준 대비 민감도·특이도 산출
- **명명 규칙(§7)을 위반하면 안 된다**
- Rogan-Gladen 보정으로 코퍼스 수준 retain 규모 추정, 부트스트랩(층화 재표집, 10,000회
  이상)으로 95% CI
- 출력 `research/synthesis/ai_reference_evaluation.json`

**P2-4. 한계 명시.** 산출물과 논문 모두에 다음을 기록한다.
- 참조표준이 AI 이므로 이 지표는 진실 대비 정확도가 아니라 **참조표준 재현도**다
- 분류기와 참조표준이 같은 모델 계열이면 독립성이 부분적이다. 실제로 쓴 모델을 명시한다
- 사람 판정은 0건이다

### P3 — 파생 체인과 사이트 재생성

**P3-1.** `npm run research:refresh`
(compare → build:systematic-review-v3 → check:translations → prepare:knowledge)
- `manifest.json` 에 `llm_gate.applied == true` 가 찍혀야 한다. 이게 이번 작업의 핵심 산출물이다
- `regex_passed`, `dropped_by_llm`, `kept` 를 기록

**P3-2. 번역.** core 집합이 바뀌면 `key_finding_translations_ko.json` 에 누락이 생기고
`validate_core_evidence_v3.py` 가 invalid 로 떨어진다. 원래 사람이 채우는 파일이다.
- `npm run check:translations -- --emit` 으로 대기열을 뽑는다
- 에이전트가 채우되, 매니페스트에 `translation_authorship: "ai_generated"` 를 기록한다
- 원문 의미를 바꾸지 않는다. 수치·단위·방향(증가/감소)을 임의로 바꾸면 안 된다

**P3-3. 개인화 확장.** 현재 규칙 5개는 연구질문 5개와 1:1 이라 "개인 특성에 맞춘다"고
하기에 얇다. core evidence 에서 실제로 관찰 가능한 축으로만 확장한다
(연령대·성별·병용약·기저질환·용량 구간 등, 초록에서 확인 가능한 것에 한정).
관찰되지 않은 축을 만들어내지 않는다. 확장한 축과 근거 행 수를 매니페스트에 기록한다.

**P3-4. 검증·배포.** `npm run typecheck && npm run lint && npm test && npm run build`
→ 경계 테스트 유지 확인 → `npx vercel --prod --yes` (GitHub 연동이 없어 push 로는 배포되지 않는다).

### P4 — AI 자율 PICOS 트랙 (v3.0 병렬)

여기서부터 새 코퍼스를 만든다. 기존 트랙은 이미 P3 까지 완결돼 있어야 한다.

**P4-1. AI PICOS 생성.** 에이전트가 연구 배경만 받고 독립적으로 설계한다.
- 입력으로 주는 것: 연구 주제 서술(고위험 임상상황의 영양보충제 안전성), 자료원 제약
  (PubMed only), 산출 형식
- **입력으로 주지 않는 것: 기존 A1~B3 질문, 기존 검색식, 기존 결과 수치.** 오염되면
  비교가 무의미해진다
- 출력 `research/searches_v3/ai_picos/picos_definition.json` —
  질문별 P·I·C·O·S, 근거, PubMed 검색식(MeSH + tiab), 예상 hit 규모
- 프롬프트 전문과 해시를 저장한다. 생성 시각·모델을 기록한다

**P4-2. 사람 트랙과 비교.** `tools/compare_picos_tracks.py`
- 질문 수준: AI 질문이 기존 A1~B3 를 포괄하는가, 새로 만든 질문이 있는가
- 검색식 수준: 용어 집합 Jaccard, MeSH 사용 여부, 필드 태그 사용 패턴
- 결과 수준: 실제 hit 수, PMID 집합의 교집합·차집합
- 출력 `research/synthesis/picos_track_comparison.json`

**P4-3. 실검색.** PubMed E-utilities. 무료이며 API 키 없이도 동작한다(초당 3회 제한).
- **새 경로에만 쓴다**: `research/searches_v3/<question_id>/pubmed/<run_id>/`
- 기존과 동일한 방식으로 `query.txt`, `efetch_*.xml`, `checksum.sha256`,
  `response_metadata.json` 을 남긴다
- `research/searches_v3/search_log.csv` 에 실행 기록
- 총 hit 이 60,000행을 넘으면 즉시 중단하고 보고한다. 상한 없이 돌리지 않는다

**P4-4. v3 코퍼스 구축과 선별.** P0~P1 과 동일한 하네스를 재사용한다.
- `data/curated_v3/evidence_map.csv` 생성
- 전량 AI 선별, 커버리지 100%
- P2 와 동일한 방식으로 참조표준 420건 층화 표본을 새로 뽑아 채점

**P4-5. 트랙 간 결론 비교.** 두 트랙의 core evidence 가 얼마나 겹치는지, 개인화 규칙이
달라지는지 기록한다. 이것이 v3.0 트랙의 주된 결과다.

### P5 — 검증 부채와 논문

**P5-1. CI red 정리.** 현재 상시 실패 중이며 원인이 각각 다르다. 구분해서 처리한다.
- `validate:phase07:proxy` — 2인 독립 선별·전문가 gold 가 없어서 실패한다. 이는 **의도된

## 5. 명명 규칙 (위반 금지)

AI 참조표준 기반 지표는 이름만 보고도 출처를 알 수 있어야 한다.

| 쓰지 말 것 | 쓸 것 |
|---|---|
| `sensitivity` | `sensitivity_vs_ai_reference` |
| `specificity` | `specificity_vs_ai_reference` |
| `accuracy` | `agreement_vs_ai_reference` |
| `gold standard` | `ai_reference_standard` |
| `validated` | `ai_cross_checked` |
| `true positive` | `reference_positive_classifier_positive` |

논문 본문에서도 "민감도"를 단독으로 쓰지 않는다. "AI 참조표준 대비 민감도"로 쓰고,
첫 등장 시 참조표준이 AI 로 생성됐음을 각주로 명시한다.

## 6. 중단과 재개

토큰이 소진되거나 시간이 끊길 수 있다. 다음을 지키면 언제 끊겨도 이어서 할 수 있다.

- 배치 단위로만 진행한다. 배치 중간에 끊겨도 완료된 배치는 유효하다
- 체크포인트 JSONL 은 append 전용이다. 절대 다시 쓰지 않는다
- 각 단계 종료 시 커밋한다. 단계 중간 상태로 커밋하지 않는다
- 중단 시 `research/logs/RESUME.md` 에 다음을 남긴다:
  현재 단계, 완료 행 수, 다음 명령, 미해결 문제
- **부분 실행 결과를 완전한 것처럼 매니페스트에 쓰지 않는다.** `run_complete` 를
  거짓으로 채우지 않는다. 커버리지 가드를 우회하지 않는다
